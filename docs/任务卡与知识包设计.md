# 任务卡与知识包设计（草案，待定）

> 目的：让任务助手在**没有游戏数据表**的公开版里也好用，而且这套做法换一个同类游戏也能用。
> 冒险岛怀旧服是第一个用它做出来的例子，以后做成 Skill 时交出去的是**方法**（格式 + 流程 + 规则），不是冒险岛的内容。

## 1. 原则

1. **通用优先**：概念、格式、流程不写死某个游戏；游戏不同的地方放进“游戏适配”和“知识包”。
2. **只写事实，用自己的话**：从公开攻略里取“谁给的、在哪、打什么、交给谁”这类事实，自己重新写；不抄原句，不放游戏原文、游戏数据表、图片。每条注明参考了哪个网站。
3. **没核实的标出来**：攻略之间说法不一样、或者自己没玩到的，标“没核实”，界面上照样显示，但写明。
4. **玩的时候再核对**：卡上写的和屏幕上看到的（自己走过的路、见过的 NPC、打过的怪）不一样时，以看到的为准，并写进日志。
5. **每一步都有日志**：认没认出是哪张卡、为什么没认出、用了卡上哪一条，都要记。

## 2. 三层结构

| 层 | 内容 | 换游戏时 |
|---|---|---|
| **通用底座** | 截图、识别、翻译、日志；通用概念（下一节）；从屏幕学东西的规则（看到几次才算、认花的名字怎么合并）；任务助手的“接 → 做 → 交”；资料互传 | 不改 |
| **游戏适配** | 这个游戏界面上的东西在哪、长什么样：小地图标题、任务窗口、任务追踪框、名牌颜色、捡东西提示的句式（如 `Lv. 5 Stump`、`x1 earned`） | 填一份配置，补几个小的识别函数 |
| **知识包** | 这个游戏的任务卡、地点、NPC、敌人、物品掉落（全是事实，自己写的） | 用同一条流程重新生成 |

知识包的内容有三个来源，最后合在一起用：

1. **攻略整理**：用第 7 节的流程，从公开攻略整理成任务卡（随程序带，或作为资料导入）。
2. **自己玩出来的**：玩的时候自动记下的路、NPC、怪、掉落（现在的“自动记走过的地图”等）。
3. **别人分享的**：玩家导出自己的记录或心得（`.mogu` 文件）互传；导入时按“不可信”处理，只收固定格式，合并时自己的优先。

> 卡和自己记下的不一样时以看到的为准；别人分享的只补自己没有的。

## 3. 通用概念（所有游戏共用的词）

- **任务**：有名字；可能属于一组（同名、分几段，如冒险岛 “Nella & Kerning City Citizens” 下的 Don Hwang、Shumi 两个委托）。
- **步骤**：接 → 做 → 交。“做”里可以有多个目标。
- **目标**：打（某敌人 N 只）、收集（某物品 N 个）、找人（和某 NPC 说话）、去某地、升到某级、用某物品。
- **地点**：有名字，属于某个区域（城镇 / 野外），地点之间有路（门、传送、坐车）。
- **NPC**：在某地点；能给任务、收任务、卖东西、送人去别处。
- **敌人**：有名字、等级，出现在若干地点；会掉若干物品。
- **物品**：有名字；从敌人掉、从 NPC 买、或任务给。

## 4. 任务卡格式

一张卡对应一个任务（一组里的每一段各一张）。JSON，字段都用游戏里的**英文原名**（屏幕上就是英文，方便对上），说明文字用中文。

```json
{
  "id": "mcw.nella-citizens.don-hwang",
  "title": "Nella & Kerning City Citizens",
  "part": "Don Hwang's Request",
  "zh": "Don Hwang 的委托",
  "level": { "min": 10 },
  "start": { "npc": "Nella", "place": "Kerning City" },
  "steps": [
    { "do": "collect", "what": "Orange Mushroom Cap", "n": 10, "from": ["Orange Mushroom"] },
    { "do": "collect", "what": "Pig's Ribbon", "n": 10, "from": ["Ribbon Pig"] }
  ],
  "end": { "npc": "Nella", "place": "Kerning City" },
  "tips": [
    { "at": "start", "text": "接的时候要付 1,000 金币" },
    { "at": "Pig's Ribbon", "text": "丝带只有蝴蝶结猪掉" }
  ],
  "next": "mcw.nella-citizens.shumi",
  "src": ["mapleclassic.wiki", "maplestory-classic.com"],
  "checked": true
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✓ | 自己起的编号：`游戏.任务组.段`，只用来引用，不用游戏内部编号 |
| `title` | ✓ | 任务窗口里的任务名（英文原样） |
| `part` |  | 同名任务的副标题（如 `Shumi's Request`），用来区分同一组里的几段 |
| `zh` | ✓ | 中文叫法（自己起的，面板上显示） |
| `level` |  | `min` 接任务要几级；`end` 交任务要几级 |
| `start` / `end` | ✓ | 给任务、收任务的 NPC 和所在地点。不知道就写 `null`，不要猜 |
| `steps` | ✓ | 目标列表。`do`：`kill` / `collect` / `talk` / `go` / `level` / `use` / `jump` / `party`；`what` 名字；`n` 数量；`from` 谁掉（收集时）；`where` 去哪几张图打 / 捡（可选）。`jump`：跳跳图（从哪进、分几段、到顶拿什么、掉下去回到哪）；`party`：组队任务（几个人、每一关做什么），这两种的帮助方式和打怪不一样，单独算 |
| `tips` |  | 提醒。`at` 指明属于哪一步（`start`、`end`、目标名），面板只在那一步显示 |
| `next` / `prev` |  | 连着的任务 |
| `src` | ✓ | 参考了哪些网站（只写网站，不贴原文） |
| `checked` | ✓ | `true` 两个来源一致或自己玩过；`false` 只有一个来源、或几个来源说法不一样：照样显示，但在那一条后面标“（没核实）”，提醒可能不准 |

另外三张小表（同一个知识包里）：

- **地点**：名字、区域、相邻地点和怎么走（门在左 / 右、坐车、找 NPC 送）、有没有隐藏门。
- **敌人**：名字、等级、中文叫法、出没地点、掉的任务物品。
- **NPC**：名字、所在地点、做什么（给任务、卖药、送人）。

> 现有的 `QuestTips.json`（12 个任务的 notes、spots、ways、from、mobs）会整体换成这个格式；旧字段的内容一条不丢，搬进新格式。

## 5. 怎么认出是哪张卡

打开任务窗口、或任务追踪框里出现任务时，按下面的顺序找卡，**分数够才用，分不清就不用**（宁可不显示也不显示错的）：

1. 任务名（`title`）对上，容许认花一两个字母。
2. 同名的一组里，再看副标题（`part`）和目标名：目标名一样都对不上的不是这张。
3. 任务名被截断（`Nella & Kerning City Cit...`）时，按开头对，再按目标名分。
4. 只有追踪框、没有任务名时，只按目标名（名字 + 数量）认。
5. 都对不上：退回现在的做法（只用屏幕上读到的），日志记“没有卡：任务名、目标名”，方便以后补卡。

认花的目标名（`Ribber Pig`、`Leat`）先用卡里的名字纠正，再显示。

## 6. 任务助手怎么用卡

面板固定写成三步：

1. **接**：找谁、在哪；不够级写“先升到 N 级”。
2. **做**：每个目标一行：打什么 / 收集什么（谁掉）、去哪几张图、进度（从屏幕读）。卡上的提醒显示在对应的那一行下面。
3. **交**：交给谁、在哪；东西没齐时写还差什么。

每一项的信息按这个顺序取，前面的没有才用后面的：

| 优先 | 来源 | 例子 |
|---|---|---|
| 1 | 屏幕上现在看到的 | 进度 7/10、任务窗口里写的 NPC 名 |
| 2 | 自己记下的（走过的路、见过的 NPC、打过的怪） | “你在 L Forest I 打过蝴蝶结猪” |
| 3 | 任务卡 | “丝带只有蝴蝶结猪掉”“Nella 在废弃都市” |
| 4 | 都没有 | 写“还不知道”，不猜 |

画面上的箭头：卡上写了目的地、自己又走过去那里的路，就带路；路没走过，就写“从哪张图进、找什么门”（卡里地点表有的话）。

卡和自己看到的对不上时（比如卡说 NPC 在 A 城，你在 B 城见到他），以看到的为准，日志记一条“卡和实际不符”，以后修卡。

## 6.5 修正：越玩越准

攻略是“起点”，玩家实际看到的是“最新的事实”。游戏改了任务条件、怪换了地方、NPC 挪了位置，玩家在屏幕上看到的一定是现在的样子。所以：

1. **每条事实带出处和时间**：攻略整理（哪个网站、哪天整理的）/ 自己看到（哪天、看到几次）/ 别人分享（哪天）。
2. **看到的和卡上的不一样**：要多次看到才算（和现在认 NPC、认怪一样，至少两次），然后**用看到的替换卡上那一条**，卡上旧的留作记录、不再显示，日志记“卡和实际不符：旧 → 新”。
3. **替换后的事实跟着资料互传**：导出 `.mogu` 时带上修正过的条目（只有事实，不带聊天、截图）；别人导入后，比他手上的旧说法新、而且看到次数够的，就替换。
4. **知识包更新时**：新版攻略整理和玩家修正冲突的，以较新的、看到次数多的为准；拿不准的两种都留着，标“说法不一”。

这样循环下去，资料会越来越接近游戏现在的样子。

## 7. 生成流程（做知识包）

同一条流程，换游戏只换输入：

1. **列来源**：这个游戏的公开攻略站。先读每个站的使用条款和 `robots.txt`，记下能不能用、能不能自动读、要怎么注明来源、能不能用在收费产品里；不允许的站不用，只允许“参考”的站只用来人工核对。
2. **列任务清单**：从攻略站的任务目录列出全部任务名（按地区、等级）。
3. **逐个读、抽事实**：每个任务读攻略页，只抽事实：任务名、副标题、等级、接 / 交 NPC 和地点、目标、谁掉、怎么走、要注意的坑。访问要慢（每页之间停一会），只读公开页面。
4. **用自己的话写卡**：按第 4 节的格式填；提醒用自己的话写，不抄句子。
5. **对照**：同一个任务有两个来源时互相对照，一致的标 `checked: true`，不一致或只有一个来源的标 `false`，并在提醒里写清哪里不确定。
6. **自动检查**：格式对不对；卡里出现的 NPC、地点、敌人在三张小表里都有；同一组任务的 `part` 不重复；数量是正整数；没有长句和原文一样（防止抄写）。
7. **抽查**：每批随机挑几张卡，在游戏里实际做一遍对照，结果记下来。
8. **出版本**：知识包带版本号和日期；改卡的记录写清改了什么、为什么。

流程本身（第 1～8 步的说明、检查脚本、卡的格式定义）是通用的，以后放进 Skill。**Skill（收费）只教方法、不带任何游戏的数据**：学的人用这套流程给自己玩的游戏做知识包，第 1 步的条款检查是方法的一部分，必须照做。某个游戏跑出来的知识包，只在对应的开源程序里按那个攻略站的条款处理。

## 8. 冒险岛怀旧服第一批

- **范围**：全部能查到的任务（参考：自用版资料里怀旧服有约 390 个任务）。按地区、等级分批做，每批做完就能用，不用等全部做完。
- **顺序**：先做你身上正在做的任务、维多利亚岛 1～30 级；再到 30 级以上、其他地区。
- **来源（2026-11-25 查过条款）**：

| 网站 | 条款 | 怎么用 |
|---|---|---|
| maplestory-classic.com | 自己写的文字 ©，只许短引用并注明；任务、NPC、地图等数据来自 OSMS Data Explorer（CC BY 4.0）；掉落来自 NiaDB（条款没查）；允许正常速度读取 | **主要来源**：只取事实（谁给、在哪、目标、等级），自己写；慢慢读；卡上注明来源 |
| OSMS Data Explorer | CC BY 4.0（要注明出处，可商用） | 上一个网站的数据源头，需要时直接核对 |
| mapleclassic.wiki | CC BY-NC-SA 4.0：不许商用（含广告、收费）、改编后要用同样的许可；`robots.txt` 写明不许 AI 爬取、只许“参考” | **不自动读取**；只人工打开个别页面核对说法；它的内容不进收费版 |
| NiaDB（掉落） | 网站自己的内容 ©；单条事实可用但要注明并链接到具体页面；整库、整批取用要先征得同意；不许未经许可用程序抓取、不许未经同意商用；`robots.txt` 禁止 AI 爬虫 | **不批量取用**。任务卡里“谁掉”这一项来自它（经 maplestory-classic.com），单独标 `fromSrc: NiaDB`，只自用测试；公开前要么去掉、换成玩家自己记到的，要么写信请求许可 |
| maplestory-classic.com 的怪物页（88 种）、地图页（342 张） | 数据来自 OSMS（CC BY 4.0）；页面上的掉落表来自 NiaDB | 等级、出没地图、地图连接可以用（同任务页的做法）；掉落表不用 |
- **每批交付**：卡（新格式）、检查结果、没核实的清单、抽查记录。

## 9. 合规

- 不放游戏原文、游戏数据表、游戏图片；只放自己写的事实说明。
- 每张卡注明参考网站；遵守各站条款，不允许的不用。
- 程序运行时不联网查攻略：知识包是提前做好、随程序或作为可选资料装上的。
- 截图识别的红线不变（只截游戏窗口、不存图、不碰游戏进程、不发按键）。

## 10. 已定 / 待定

已定（2026-11-25 用户）：
- 三层结构、通用概念、任务卡格式可以；跳跳图、组队任务单独算两种目标。
- 知识包三个来源：攻略整理、自己玩出来的、别人分享的。
- 先做 1～30 级（维多利亚岛）看效果，再做全部。
- 没核实的也显示，标“（没核实）”。

待定：
1. 知识包随公开版自带，还是单独资料文件导入。建议：公开免费版自带（来源是 CC BY 4.0 的数据 + 自己写的说明，注明出处），但放成单独一个文件，随时能换、能拿掉；收费版到时再按条款重新确认。
2. 冒险岛的游戏内容本身归 Nexon，任务事实写进程序是否稳妥，公开前再看一次 Nexon 条款。
